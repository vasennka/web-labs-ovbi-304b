Документ для двух ситуаций: «надо быстро показать работу» и «надо сдать ссылку на репозиторий».

## Часть 0. Что должно быть установлено

| Инструмент | Версия | Проверка |
|---|---|---|
| Node.js | 18+ (у меня проверено на 22.22) | `node -v` |
| npm | 9+ (идёт с Node) | `npm.cmd -v` — см. примечание ниже |
| Git | любая свежая | `git --version` |

### ⚠ Главная ошибка новичка: «Syntax error, 800A03EA» при двойном клике по laba1.js

Если дважды щёлкнуть по файлу `laba1.js`, Windows запускает его **не через Node.js**,
а через старый движок «Windows Script Host» (JScript). Он не понимает современный
JavaScript, поэтому появляется окно:

```
Script:  ...\laba1.js
Line:    29
Error:   Syntax error
Code:    800A03EA        ← движок WSH не понял синтаксис JS (не ошибка в работе!)
```

**Как запускать правильно — три способа:**

1. **Ярлыки в папке `ЗАПУСК`** (самый простой, двойной клик):
   * `Запустить лабу 1.cmd` … `Запустить лабу 7.cmd` — по одной работе;
   * `Запустить ВСЕ лабы 1-7 и сохранить вывод.cmd` — сразу все; вывод каждой
     работы сохраняется в файл `вывод_лабаN.txt` в главной папке (удобно для скриншотов);
   * `Запустить лабу 8 (сервер).cmd`, `Проверить лабу 8 (без браузера).cmd`;
   * `Установить проект (запустить один раз).cmd`, `Запустить проект (сервер).cmd`,
     `Проверить проект (автотест).cmd`;
   * `Демонстрация Git (лаба 2).cmd` — создаёт настоящий git-репозиторий с ветками и конфликтом;
   * `Открыть инструкцию.cmd` — открывает этот текст и папку с Word-докладами.

2. **Из командной строки** (так написано в методичке): открыть `cmd`, перейти в папку
   с работами (`cd /d "C:\Users\Vasenka\Desktop\проектирование веб сайт"`) и выполнить `node laba1.js`.

3. **Необязательно: сделать двойной клик рабочим навсегда.** Файл
   `ЗАПУСК\Сделать двойной клик по .js рабочим.cmd` → правая кнопка →
   «Запуск от имени администратора». После этого `.js` будет открываться Node.js.
   Вернуть как было: `assoc .js=JSFile` и
   `ftype JSFile="C:\Windows\System32\WScript.exe" "%1" %*`.

Краткая памятка про это лежит рядом: `ПРОЧТИ_ЕСЛИ_ЛАБЫ_НЕ_ЗАПУСКАЮТСЯ.txt`.

> **Важно для Windows.** Если `npm -v` выдаёт ошибку вида
> «File C:\Program Files\nodejs\npm.ps1 cannot be loaded because running scripts is disabled»,
> значит в PowerShell запрещены скрипты. Есть два решения:
> 1. писать команды с расширением: `npm.cmd install` (работает всегда, ничего менять не надо);
> 2. один раз разрешить скрипты: открыть PowerShell **от администратора** и выполнить
>    `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` — после этого обычный `npm install` заработает.

## Часть 1. Запуск лабораторных работ №1–7

Это обычные консольные файлы, зависимостей нет — ставить ничего не нужно.

```powershell
cd "C:\Users\Vasenka\Desktop\проектирование веб сайт"   # папка с работами

node laba1.js     # циклы, массивы, функции
node laba2.js     # «Анализ успеваемости» (командная разработка)
node laba3.js     # функции, стрелки, замыкания
node laba4.js     # чистые функции, рекурсия, map/filter/reduce
node laba5.js     # объекты, прототипы, наследование
node laba6.js     # классы, ошибки, && || ??
node laba7.js     # EventEmitter и потоки (создаёт файлы в laba7/data)
```

**Что выводится.** Каждый файл печатает в консоль результаты всех заданий и итог в виде
`✔`/`✘` (самопроверка), а в конце — письменные ответы на контрольные вопросы.

**Скриншоты для отчёта.** Запустите файл и сделайте скриншот консоли, как просит методичка.
Удобно так — с сохранением вывода в текстовый файл:

```powershell
node laba1.js | Tee-Object -FilePath laba1-вывод.txt
```

**Повторный запуск лабы №7.** Файл создаёт `laba7/data/input.txt`, `copy.txt`,
`result.txt`. Удалить и пересоздать всё можно так: `Remove-Item laba7\data -Recurse; node laba7.js`.

## Часть 2. Запуск лабораторной №8 (React + AJAX/Comet/WebSocket)

Здесь нужен один пакет `ws` (для WebSocket-сервера):

```powershell
cd "C:\Users\Vasenka\Desktop\проектирование веб сайт"
npm install            # или npm.cmd install — поставит ws
node laba8.js          # сервер на http://localhost:3000
```

Откройте в браузере:

| Адрес | Что показывает |
|---|---|
| http://localhost:3000/ | React-приложение: два ProgressBar с разной скоростью |
| http://localhost:3000/ajax.html | Задание 2: AJAX + опрос раз в 2 секунды (откройте **в двух вкладках**) |
| http://localhost:3000/poll.html | Задание 3: Comet / long polling |
| http://localhost:3000/ws.html | Задание 3: WebSocket |
| http://localhost:3000/sse.html | Server-Sent Events |
| http://localhost:3000/jsonp.html | JSONP |

**Как снять «доказательства» для отчёта:**
1. Откройте `ajax.html` в двух вкладках, отправьте сообщение в первой — оно появится во второй.
2. Нажмите F12 → вкладка **Network**, посмотрите: каждые 2 секунды уходит `GET /api/messages`
   (это цена периодического опроса — вкладка «сколько всего запросов»).
3. Перейдите на `poll.html` и убедитесь, что там **один висящий** запрос `pending`
   вместо запросов каждые 2 секунды.
4. На `ws.html` в Network будет один запрос `101 Switching Protocols`, дальше — кадры WebSocket.

Остановить сервер: `Ctrl+C`.

Автопроверка без браузера (полезно, чтобы снять скриншот «всё работает»):

```powershell
node laba8.js --selftest
```

React-приложение задания 1 можно запускать отдельно с hot reload:
`cd laba8\progress-app; npm install; npm run dev` → http://localhost:5173
Оно уже собрано в `laba8/progress-app/dist`, поэтому обычный сервер его отдаёт и без этой команды.

## Часть 3. Запуск проекта (тема 25)

Проект = бэкенд (Node.js + Express + EJS) + фронтенд (React + Vite).

```powershell
cd "C:\Users\Vasenka\Desktop\проектирование веб сайт\project"

# 1) поставить зависимости бэкенда и фронтенда
npm run install:all

# 2) наполнить базу (админ, 3 новости, 6 фотографий, раздел «О нас»)
npm --prefix backend run seed

# 3) собрать React-приложение (результат кладётся в frontend/dist)
npm run build

# 4) запустить сервер
npm start
```

Открыть:

| Адрес | Что это | Логин |
|---|---|---|
| http://127.0.0.1:4000/ | Публичная часть на **React** | — |
| http://127.0.0.1:4000/site/ | Та же публичная часть, но отрисована **шаблонизатором EJS** (шапка/подвал/страницы) | — |
| http://127.0.0.1:4000/admin/login | **Админка** | `admin` / `admin123` |
| http://127.0.0.1:4000/api/v1/news | **REST API** | — |

**Сценарий демонстрации на защите (5 минут):**
1. Публичная часть React: главная → карусель галереи (скажите: «самодельный контрол,
   умеет drag, клавиатуру, автопаузу») → галерея с фильтром по категориям → новости → отдельная новость.
2. Контакты: отправьте сообщение, поставив оценку звёздами (второй самодельный контрол).
3. `/site/` — покажите, что те же данные отдают серверные шаблоны EJS (в том числе форма,
   работающая **без JavaScript** — можно отключить JS в браузере).
4. `/admin/login` — попробуйте войти с неверным паролем (ошибка), затем `admin/admin123`.
   В админке: дашборд → добавьте новость → добавьте фото (загрузите файл) → раздел
   «Обратная связь» (там ваше сообщение из шага 2) → «О нас» (видны данные интеграций).
5. Откройте http://127.0.0.1:4000/api/v1/integrations — покажите живые данные GitHub
   (через официальный SDK) и погоду (через свой клиент поверх `fetch`), и что при
   отсутствии интернета отдаётся кэш/заглушка, а сайт продолжает работать.

**Проверка, что всё цело** (28 автотестов: API, валидация, EJS-страницы, вход в админку,
CSRF, отдача SPA):

```powershell
npm --prefix backend run smoke
```

**Полезные варианты запуска:**

```powershell
# режим разработки: бэкенд с автоперезапуском + Vite с hot reload (порт 5173)
npm run dev

# сменить файловое хранилище на SQLite (встроенный node:sqlite)
$env:DATA_DRIVER="sqlite"; npm --prefix backend run seed; npm start

# другой порт и пароль администратора
$env:PORT="5000"; $env:ADMIN_PASSWORD="SvoiParol123"; npm start
```

**Если что-то не работает:**

| Симптом | Причина и решение |
|---|---|
| `npm : File npm.ps1 cannot be loaded` | политика PowerShell → используйте `npm.cmd` (см. Часть 0) |
| Порт занят (`EADDRINUSE`) | другой сервер уже запущен: `$env:PORT="4001"; npm start` |
| Сайт пустой, «фронтенд ещё не собран» | выполните `npm run build` в папке `project` |
| Админка не пускает с `admin123` | пароль менялся; удалите `backend/data/db.json` и запустите `npm --prefix backend run seed` заново |
| В логах `SQLite is an experimental feature` | это нормальное предупреждение Node 22, работе не мешает |
| Интеграции показывают «сервис недоступен» | нет интернета — это предусмотренный сценарий: отдаётся кэш/заглушка, сайт работает |

## Часть 4. Как выложить всё это на GitHub

> **Самый простой путь (ничего вводить вручную не нужно).** В папке `ЗАПУСК` есть два ярлыка:
> * `ВЫЛОЖИТЬ НА GIT (заполнить и запустить).cmd` — первая публикация: спросит имя, email,
>   логин GitHub и название репозитория, сделает коммит, откроет страницу создания
>   репозитория и выполнит push;
> * `Отправить изменения на Git повторно.cmd` — когда что-то поправили и нужно обновить
>   репозиторий (коммит + push одной кнопкой).
>
> Всю цепочку я проверил на тестовом локальном репозитории: 173 файла доходят целиком,
> `node_modules`, `.env`, база данных и сборки в репозиторий не попадают.
> Ниже — тот же процесс руками, если хочется понимать каждую команду.

### 4.1. Что не должно попасть в репозиторий

В корне уже лежит файл `.gitignore`. Он исключает:

* `node_modules/` — зависимости восстанавливаются командой `npm install`;
* `project/backend/data/db.json` и `db.sqlite*` — база создаётся скриптом `seed`;
* `project/frontend/dist/` и `laba8/progress-app/dist/` — сборки создаются командой `npm run build`;
* `.env` — **секреты не коммитим никогда**;
* `laba2/git-demo/` — демонстрационный репозиторий пересоздаётся скриптом.

> Хотите, чтобы сайт работал сразу после клонирования, без `seed`? Тогда уберите из
> `.gitignore` строку `project/backend/data/db.json` — файловая база уйдёт в репозиторий.

### 4.2. Первый коммит и отправка на GitHub

**Шаг 1. Создайте пустой репозиторий на GitHub** (веб-интерфейс):
github.com → **New repository** → имя, например `web-labs-prisma` → **Public** →
**не** ставьте галочки «Add README / .gitignore / license» (они уже есть у нас) → **Create**.

**Шаг 2. Инициализируйте Git в папке с работами** (одна строка за раз):

```powershell
cd "C:\Users\Vasenka\Desktop\проектирование веб сайт"

git init
git branch -M main
git config user.name "Ваше Имя"
git config user.email "ваш@email.com"

git add .
git status                    # глазами проверьте: node_modules и .env НЕ должны быть в списке
git commit -m "Лабораторные работы №1-8 и проект: фотостудия PRISMA"

git remote add origin https://github.com/ВАШ_ЛОГИН/web-labs-prisma.git
git push -u origin main
```

**Шаг 3. Авторизация.** GitHub больше не принимает пароль от аккаунта по HTTPS.
Вариант с токеном (проще):
1. GitHub → ваша аватарка → **Settings** → **Developer settings** → **Personal access tokens**
   → **Tokens (classic)** → **Generate new token (classic)**;
2. отметьте галочку **repo**, задайте срок, нажмите Generate и скопируйте токен (он показывается один раз);
3. при `git push` в качестве пароля вставьте **этот токен** (логин — ваш ник).
4. Чтобы не вводить каждый раз: `git config --global credential.helper manager` (в Windows
   токен запомнится в диспетчере учётных данных).

Вариант с SSH-ключом: `ssh-keygen -t ed25519 -C "ваш@email.com"` → скопировать содержимое
`~/.ssh/id_ed25519.pub` в GitHub → **Settings** → **SSH and GPG keys** → **New SSH key**,
и использовать адрес `git@github.com:ВАШ_ЛОГИН/web-labs-prisma.git`.

**Шаг 4. Что написать в описании репозитория** (About → справа сверху):
описание + теги `javascript nodejs react express ejs` — преподавателю проще ориентироваться.

### 4.3. Как отправлять изменения (обычный цикл)

```powershell
git status                          # что изменилось
git diff                            # что именно изменилось
git add laba3.js                    # добавить конкретный файл (или git add . — все)
git commit -m "laba3: добавлены ответы на контрольные вопросы"
git push                            # отправить на GitHub
```

Полезно на защите: в разделе **Commits** видно историю — можно показать, что работы
делались по шагам, а не одним куском. Ветки и Pull Request из лабораторной №2 применимы
и здесь: `git switch -c feature/news-editing`, затем PR в `main`.

### 4.4. Как сдать ссылку

Отправьте преподавателю:

```

Лабораторная №8:   laba8.js + laba8/ — запуск: npm install && node laba8.js (порт 3000)
Проект (тема 25):  project/ — запуск: npm run install:all && npm --prefix backend run seed && npm run build && npm start (порт 4000)

Как запускать:     ИНСТРУКЦИЯ.md
```

### 4.5. Можно ли сделать «живую» ссылку на сайт?

* **GitHub Pages** — подходит только для статики. Из этого проекта так можно выложить
  доклады и страницы лабораторной №8 (они статические). Бэкенд на Pages не работает:
  нет Node-процесса, БД и админки.
* **Реальный хостинг** (Render / Railway / VPS) — подойдёт для проекта: сборка `npm install`,
  команда запуска `npm --prefix backend start`, порт задаёт переменная `PORT`.
  Ограничение, о котором честно стоит сказать на защите: файловая база (`db.json`)
  на бесплатных тарифах может обнуляться при перезапуске контейнера — для демонстрации
  это нормально, а для продакшена нужен внешний Postgres.

**Если решили выложить доклады на GitHub Pages:**

```powershell
# в репозитории: Settings -> Pages -> Source: Deploy from a branch -> main / (root)
# доклады в формате Markdown GitHub отрендерит сам, достаточно ссылаться на них:
#   https://ВАШ_ЛОГИН.github.io/web-labs-prisma/doklady/
```

Рядом (`doklady/*.md`) лежат исходники в Markdown — их удобно править и коммитить в Git.
Если нужно поменять текст и пересобрать Word-версию, есть конвертер (без внешних библиотек):

```powershell
cd "C:\Users\Vasenka\Desktop\проектирование веб сайт"
node tools\md2docx.js doklady\01-mvc-mvp-mvvm.md --out=doklady\word
# или все сразу:
node tools\md2docx.js doklady\01-mvc-mvp-mvvm.md doklady\02-arhitektura-backend-rest-api.md `
    doklady\03-proektirovanie-api-rest-graphql-grpc.md doklady\04-autentifikaciya-i-avtorizaciya.md `
    doklady\05-owasp-top-10.md doklady\06-testirovanie-i-mutacionnoe-testirovanie.md `
    doklady\07-staticheskie-analizatory.md project\DOKLAD.md --out=doklady\word
```

Что уже сделано в Word-файлах: стили заголовков (работает панель навигации),
таблицы с рамками и шапкой, блоки кода моноширинным шрифтом, нумерация страниц в подвале.
Файлы .docx собраны в стандартном формате OOXML, поэтому открываются в Microsoft Word,

Как выбрать тему: берите любую — каждая самодостаточна (введение, теория, примеры кода,
выводы и 5–7 вопросов для самопроверки). Если преподаватель просил «тему 25», уточните её
формулировку в общем списке курса: в приложенных файлах такой темы нет, поэтому доклад
в проекте (`project/DOKLAD.md` / `08-....docx`) раскрывает тему №2 из вашего списка,
напрямую связанную с техническим заданием, — на защите это легко объяснить.
